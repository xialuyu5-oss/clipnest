## Web: ready to run with the listed prerequisites

Install Python 3.11+, FFmpeg/ffprobe and Deno 2.3+ or Node.js 22+ for YouTube. Extract either Web archive and run `python start.py` (Windows users can double-click `start.bat`). Open the local address printed by the launcher; the default is `http://127.0.0.1:8000`.

- Analyze supported platform links and select the actual formats returned by the source.
- Confirm duration, estimated size and indicative transfer time before downloading. No fixed application file-size, duration or overall transfer-time ceiling.
- View speed/ETA, pause and resume supported downloads, or cancel and delete cached data.
- Keep task checkpoints and completed files across server restarts until you delete them.
- Use English by default or switch among 12 languages, with Arabic RTL and responsive controls.
- Merge separate audio/video locally on the host, then save the result through the browser.

The Web archive contains 31 deployment files. Runtimes are installed separately; this is not a standalone executable. Read the archive's included installation guide or [Web installation](../WEB_INSTALL.md). Source/platform restrictions and available disk space still apply.

## Android: independent on-device application source

The Android app embeds Python/yt-dlp, QuickJS and FFmpeg. Its bundled interface calls a restricted native bridge, without a ClipNest server fallback. It implements download confirmation, current-track ETA, pause/resume, cancellation cleanup, persistent tasks and system file export. No member-account login is implemented.

[Build locally](../../clients/android/README.md). Current test packages use development signing and the `org.clipnest.app.debug` identity. They are not production-signed releases. Shared UI, language catalogs and the message contract are prepared for a future iOS adapter; the Android engine binaries are not an iOS implementation.

## WeChat: entirely on-device, limited developer preview

Import the extracted source folder into WeChat Developer Tools, configure an actual AppID and the appropriate media-host settings, and validate it on a phone. The archive is a development project, not an installable Mini Program or an approved release.

Implemented: direct HTTPS MP4 metadata, confirmation, checked Range downloads, checkpoint resumption where safe, pause on backgrounding, cancellation cleanup and album export. Sources that cannot safely resume restart after a pause, as stated in the interface.

**Unfinished:** platform share-page extraction, HLS/DASH, separate-track merging, real Developer Tools/device acceptance and publishing. The requirement for on-device operation is preserved; no parsing server has been substituted. [WeChat guide](../../clients/wechat/README.md)

## Validation and known gaps

- Web baseline: 114 Python tests, frontend/i18n checks, actual local HTTP/HLS resumption and extracted-package startup on Windows.
- Android: both ABI builds and signature verification; three Android 16 x86_64 emulator integration tests, including bundled yt-dlp HTTP download and FFmpeg audio/video remux. Lint: 0 errors, 2 advisory warnings.
- Shared/WeChat: 12 locales with 321 keys; MP4 metadata fixtures; HTTP Range pause/reload/resume with exact-byte checks; changed-source/ignored-range handling and cancellation. wx API-specific tests use adapters, not a real WeChat runtime.
- Still unverified: representative live links across all platforms, member-HD, physical Android phones, background/large-file edge cases, WeChat devices, Docker, macOS and public hosting.
