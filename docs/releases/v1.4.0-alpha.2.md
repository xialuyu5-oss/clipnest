# ClipNest v1.4.0-alpha.2 — Website-first local processing

Open the website, check this computer, and continue automatically to the full
downloader. Only missing components need installation. The website distributes
the interface and packages; extraction, downloads and merging run on the user's
device, without a ClipNest media relay.

**通过 OpenAI Vibe Coding（OpenAI ChatGPT 与 Codex）开发。** This is an independent
project, directed by the user, not an official OpenAI product.

## Start here / 从这里开始

[Website entry / 网站入口](https://xialuyu5-oss.github.io/clipnest/)

- Ready: the current tab opens the complete local downloader at
  `http://127.0.0.1:8000/`, keeping the chosen language.
- Missing components: the page lists the verified missing items and their install
  links. The Windows helper checks again and asks before each installation.
- Not connected: installed software remains **unknown**. Start the component,
  install it on first use, or review the browser's local-connection permission.

首次使用需下载、解压 PC 包，运行 `install-missing.bat` 确认补齐缺项，再运行
`start-local.bat`。返回网站后重新检测，就绪自动进入完整界面。组件需要保持运行；
目前没有后台自动启动服务。浏览器可能询问本机连接权限。

## Changes

- Replaced the software-directory entrance with automatic environment checking.
  Checks Python, FFmpeg/ffprobe, a compatible Deno or Node runtime, and yt-dlp/EJS.
- Kept the complete existing quality selection, per-download confirmation,
  duration/size/time estimates, pause/resume, cancellation cleanup and persistent
  tasks. No fixed application file-size, duration or total-time limit was added.
- Website checks expose only readiness flags. Download/account APIs retain their
  same-origin session and CSRF controls; the website cannot read local task files.
- Added explicit local mode with separate storage, loopback-only binding and no
  configured media proxy, without changing an existing `.env`.
- Android source now accepts shared text links and supports `clipnest://open`.
  Sharing only fills a validated link; it does not automatically analyze/download.
- Kept English default and 12 languages, Arabic RTL and usable narrow controls.
- Added a manually triggered Pages workflow. Source uploads alone do not publish
  or redeploy the website.

## Validation and remaining limits

Local evidence: 134 Python regression tests including discovery/environment
checks; Web/frontend/i18n tests; browser disconnected, missing-FFmpeg fixture and
actual-ready handoff; chosen-language persistence; narrow-layout checks. The
extracted PC package started with stale hosting settings and passed actual
discovery, confirmation, original-demo transfer and cache deletion checks.
Release-version checks are recorded in the publication manifest.

Android ARM64/x86_64 development builds and four emulator tests were verified in
the preceding local iteration. **No APK is attached**: native corresponding-source
and notices remain incomplete. Production signing and real-phone/live-platform
acceptance are also pending. [Distribution details](../../clients/android/NATIVE_DISTRIBUTION.md).

The WeChat project is unchanged and remains an on-device direct-MP4 developer
preview, without platform share-page extraction or merging. There is no iOS app,
new WeChat binary, AAB or prebuilt Docker image in this release.

Public HTTPS-to-loopback browser permission behavior must be checked after Pages
deployment. Clean-machine installation, macOS/Linux, live-platform coverage and
mobile-browser handoff are not established by local fixtures or an emulator.
The website probes default local port 8000; another port requires direct access.
